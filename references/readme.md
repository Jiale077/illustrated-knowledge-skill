# 项目图文 README

把项目介绍写成读者能跟着用起来的图文指南：先看懂用途和结果，再完成安装与第一次使用。沿用知识文章解释清楚、例子具体、图片表达关系的原则，按 README 的阅读任务调整篇章。

## 先确认实际项目

读取目标仓库已有 README、入口文件、配置模板、安装脚本、示例和相关检查。使用实际仓库 URL、命令、文件名与输出，保留已有有效内容和项目定位。涉及版本、宿主安装规则或外部依赖时查看当前一手说明，记录核实来源。

使用 Agent Reach 获取适合的平台资料，也可用仓库连接器或本地文件检查项目。以源码、实际文件和可复核的运行结果确定功能；只有亲自运行成功的步骤才写“已验证”。

## 组织阅读路线

常见顺序如下，可按项目调整：

1. **项目名与一句话介绍**：说清给谁用、能完成什么。
2. **品牌封面**：项目标题、品牌名和一条清楚的使用场景或流程。
3. **用途与产出**：用具体输入、操作和输出说明能力，必要时用小表格比较。
4. **实际效果**：选择真实示例、已有截图或生成的概念图，配合简短解释。
5. **安装和第一次使用**：前提、安装、最少配置、示例输入、结果位置与成功表现。
6. **进阶用法与常见问题**：按真实决策点补充，开发细节放后面。

开头提供少量页内导航。安装步骤让第一次接触项目的人能按顺序完成，解释配置项与占位符。代码块使用仓库中确实支持的命令，不添加尚未实现的功能或空链接。徽章只展示实际具备的状态和许可证。

## 配图与品牌

默认读取 [Jiale 的 AI 工坊视觉规范](jiale-style.md)。用户要求参照同系列项目时，先读取并查看其真实封面，以画风、配色、角色和构图作参考，内容适配当前项目。

使用原生 Image 生成封面，将提示词和最终位图保存在项目中，例如 `docs/cover-prompt.md`、`docs/images/hero-jiale-ai-workshop.png`。提示词写具体场景、信息关系与逐字标题。逐张检查品牌名、项目名、步骤标签和视觉可读性。

封面负责传达主题与使用流程；后续用实际示例或界面截图展示真实效果。概念插图配一句准确图注，避免把它写成实际界面截图。已有说明图能够解释内容时直接复用，保持用户要求不变的图不重绘。

GitHub 文档采用标准 Markdown、项目内相对图片路径与有效锚点。Obsidian callout 在 GitHub 不会呈现本包样式，需要展示定义时使用普通引用或段落。

## 保存与核对

默认交付项目内的 README、封面、必要示例和提示词。此模式不调用 Obsidian 归档脚本；用户要求额外保存笔记时再完成对应入库。

完成前检查：

- 读者能找到“能做什么、结果形式、安装与第一条操作”。
- 本地图片、相对链接和页内锚点存在，图中文字与项目实际一致。
- 安装与配置说明对应当前项目和宿主能力；写清实际核验范围。
- 需要发布的内容不包含本机路径、私人笔记、账号配置或会话信息。

已授权上传时，核对仓库当前分支和已有改动后提交，确认远端版本。只要求起草时保留本地成果。同步维护本机已安装的技能时保留其本地配置。
